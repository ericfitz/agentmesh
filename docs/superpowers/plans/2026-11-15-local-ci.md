# Local CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No paid GitHub Actions minutes outside a release; every check cloud CI ran still runs locally at a defined moment.

**Architecture:** `ci.yml` and `windows.yml` become dispatch-only. Three local runners (`scripts/windows-test.sh` over `vmrun`, `scripts/verify-linux.sh` in a Linux container, and the existing `scripts/check-gates-selftest.sh` with a commit argument) run from a path-selecting `.githooks/pre-push` and from a preflight in `release/release.sh`. They share one state directory for logs, pass records and the VM lock.

**Tech Stack:** bash (`set -euo pipefail`), VMware Fusion `vmrun`, PowerShell 5.1 and 7 in the guest, Docker, macOS `security`, Go 1.27.

**Spec:** `docs/superpowers/specs/2026-11-15-local-ci-design.md` (approved by Eric 2026-11-15).

**Deviation from the spec (Eric's decision, 2026-11-15):** the test VM is a fresh Windows 11 arm64 install, not a clone of Eric's VM. Spec Decision 6 and spec Task 3's clone and strip steps are void. The VM is `~/Virtual Machines.localized/Windows 11 Test VM.vmwarevm`, guest account `test`, encrypted (vmrun needs `-vp`), snapshot `baseline` (powered off). The snapshot holds Go 1.27.3, PortableGit 2.56.1 and PowerShell 7.7.0 in `C:\tools` on the user PATH, plus a warm `GOMODCACHE` and `GOCACHE` as of commit 653a6bd. The setup half of the spike is done (agentbus memory 1821). Task 8 records this deviation in ADR 0020.

## Global Constraints

- Every script: bash, `set -euo pipefail`, absolute paths, and a fail-fast precondition check that names the missing item. No GNU `timeout`: bound commands with `perl -e 'alarm N; exec @ARGV'`. Use `shasum -a 256`.
- No script reads `~/.keys`. Passwords come only from the login Keychain (`security find-generic-password -s <service> -a <account> -w`).
- Never touch Eric's VM `~/Virtual Machines.localized/Windows 11 64-bit Arm.vmwarevm`. `windows-test.sh` refuses that path.
- `vmrun` is `/Applications/VMware Fusion.app/Contents/Library/vmrun`, overridable by `AGENTMESH_VMRUN` (selftest seam).
- State directory (the spec's "data dir"): `AGENTMESH_DEV_STATE`, else `${XDG_STATE_HOME:-$HOME/.local/state}/agentmesh-dev`. Layout:
  - `logs/<check>/<commit>/` holds the full logs.
  - `passes/<check>/<commit>` is an empty file recorded on a pass.
  - `windows-test.lock` holds `pid start_epoch`.
- Check names: `windows-test`, `verify-linux`, `gates-selftest`, `release-preflight`.
- Runner contract (shared by `windows-test.sh`, `verify-linux.sh` and `check-gates-selftest.sh`):
  - The first argument is `COMMIT`, any rev (default `HEAD`), resolved once to a full SHA.
  - Exit 0: every step passed. Exit 1: a step failed. Exit 2: usage or a precondition failed (tool, Keychain entry, Docker down, VM already running). Exit 3: infrastructure failure (Tools timeout, guest copy failed, container failed to start).
  - Stdout carries only the summary: steps run, passed and failed, the names of failed tests, the log directory.
- Make targets take `COMMIT ?= HEAD` and pass it through: `make windows-test COMMIT=x`, `make verify-linux COMMIT=x`, `make check-gates-selftest COMMIT=x`.
- Until the first release, change formats in place: no compatibility shims (project CLAUDE.md).
- American English. Name every task and finding with a full term and a number.

## Task Bases

- Task 1 goes on `main` now. Then cherry-pick it onto `adr-0019-spec-1`. On the `ci.yml` conflict, keep the dispatch-only triggers and keep the branch's `pen-gate` job.
- Tasks 2, 5, 6, 7 and 8: on `main` after `adr-0019-spec-1` merges. The branch edits `scripts/m4-exit-checks.sh`, `scripts/m7-exit-checks.sh` and the Makefile `verify` recipe, and `pen-check` exists only there.
- Tasks 3 and 4 may run on `main` before the merge. They add new files and one Makefile target only; the target goes at the end of the Makefile so the merge stays clean.

## Review Focus

1. A push that deletes a ref, pushes a tag, creates a new branch, or force-pushes over a remote SHA that is unknown locally. The hook must never crash or pick the wrong base; it skips a deletion and leaves tags to the release preflight.
2. A killed `windows-test.sh` leaves the VM running and a stale lock. The next run must detect the dead PID, power the VM off, clear the lock and proceed. A live PID must be refused, naming that PID.
3. Docker is down for `verify-linux.sh`: exit 2 naming Docker, never a pass.
4. `core.hooksPath` is not `.githooks`, so the hook checks silently never run. `make verify` must fail locally until it is set.
5. The `baseline` snapshot's caches are older than `go.mod` or `go.sum`. The run must still pass, only slower, and its summary must say the baseline is stale and how to refresh it.
